# MetaLab — архитектура проекта

## 1. Общая концепция

MetaLab — платформа моделирования боёв между агентами с различными характеристиками и стратегиями.

Основные задачи:
- Создание сборок агентов.
- Моделирование боёв.
- Проверка эффективности стратегий.
- В перспективе — автоматический поиск сильных сборок и стратегий.

Текущая цель — MVP. Не добавлять абстракции без практической необходимости.

## 2. Основные компоненты

### Build

Неизменяемая модель сборки (`dataclass(frozen=True)`).

- Начальные характеристики: `health=1`, `damage=1`.
- Дополнительный бюджет: 10 очков.
- Стоимость единицы характеристики: 1.
- Максимальная сумма характеристик: 12.
- Минимум каждой характеристики: 1.
- Способности пока не входят в MVP.

Build принимает готовые значения и проверяет их корректность. Распределением бюджета не занимается.

### Attribute

Перечисление характеристик:

```python
class Attribute(Enum):
    HEALTH = auto()
    DAMAGE = auto()
```

### Agent

Представляет участника боя.

- Получает `Build`.
- Хранит текущие характеристики в словаре `__current_attributes`.
- Неизменяемый Build остаётся источником начальных характеристик.
- `get_attribute()` возвращает текущее значение характеристики.
- `is_alive` определяется по текущему HEALTH.
- `apply_result(ActionResult)` применяет изменение характеристики.
- Не отдаёт наружу изменяемый словарь характеристик.

### AgentSnapshot

Неизменяемый снимок характеристик агента.

- Хранит копию текущих характеристик.
- Использует `MappingProxyType` для защиты от изменений.
- Создаётся через `Agent.state`.

### AgentState

Неизменяемое состояние двух участников боя:

```python
@dataclass(frozen=True)
class AgentState:
    own_state: AgentSnapshot
    enemy_state: AgentSnapshot
```

Каждая стратегия получает состояние в собственной перспективе:
- Агент A: `own_state=A`, `enemy_state=B`.
- Агент B: `own_state=B`, `enemy_state=A`.

Оба состояния создаются на начало раунда, до выбора и исполнения действий.

## 3. Система действий

### ActionType

Перечисление типов действий.

Пока существует только:

```python
class ActionType(Enum):
    ATTACK = auto()
```

В будущем список может расширяться.

### Target

Перечисление целей:

```python
class Target(Enum):
    SELF = auto()
    ENEMY = auto()
```

### Action

Неизменяемый DTO, описывающий решение стратегии:

```python
@dataclass(frozen=True)
class Action:
    action_type: ActionType
    target: Target
```

### ActionResult

Неизменяемый DTO, описывающий изменение одной характеристики.

- `attribute` — изменяемая характеристика.
- `value` — величина изменения (дельта).
- Положительное значение увеличивает характеристику.
- Отрицательное значение уменьшает характеристику.
- Ноль означает отсутствие изменения.

### Effect

Неизменяемый DTO, связывающий `ActionResult` с получателем изменения.

- `result` — результат изменения.
- `target` — получатель эффекта (`SELF` или `ENEMY`).

Одно действие может возвращать несколько эффектов: `tuple[Effect, ...]`.

## 4. Стратегия агента

### AgentStrategy

Отвечает за выбор действия агентом.

Получает общий набор доступных действий через конструктор:

```python
class AgentStrategy:
    def __init__(self, available_actions: tuple[ActionType, ...]) -> None:
        self.__available_actions = available_actions
```

- `available_actions` — общий неизменяемый набор действий, определённый в модуле констант.
- Один и тот же набор передаётся разным экземплярам стратегий.
- `choose_action(state)` выбирает тип действия из доступного набора и определяет цель.
- Возвращает `Action`.

Текущая логика:
- Выбирается первое действие из доступного набора.
- Для `ATTACK` выбирается `Target.ENEMY`.

Пока стратегия представляет собой простой скрипт с ветвлением внутри `choose_action`. Дополнительные методы и абстракции не вводятся до появления необходимости.

## 5. Правила действий

### ActionRules

Абстрактный интерфейс для расчёта последствий действий.

```python
class ActionRules(ABC):
    @abstractmethod
    def calculate_effects(
        self,
        state: AgentState,
        target: Target,
    ) -> tuple[Effect, ...]:
        pass
```

Правила:
- Получают состояние боя и выбранную стратегией цель.
- Рассчитывают эффекты.
- Не применяют эффекты самостоятельно.
- Не выбирают цель вместо стратегии.
- Должны быть stateless.

### AttackRules

Конкретная реализация `ActionRules`.

- Рассчитывает урон на основе DAMAGE атакующего.
- Формирует `ActionResult` для HEALTH.
- Возвращает `Effect` с указанной целью.

### ActionRulesRegistry

Хранит соответствие:

`ActionType → ActionRules`

- Создаётся один раз до серии боёв.
- Содержит экземпляры правил.
- Передаётся в `BattleEngine`.
- Движок получает правила через метод `get()`.
- Не предоставляет наружу внутренний словарь.

## 6. Каталог доступных действий

### AVAILABLE_ACTIONS

Общий набор доступных типов действий.

Определяется один раз в модуле констант:

```python
AVAILABLE_ACTIONS = tuple(ActionType)
```

- Используется при создании стратегий.
- Не создаётся отдельно для каждой стратегии.
- Неизменяем.
- Пока содержит только `ActionType.ATTACK`.

Каталог доступных действий и `ActionRulesRegistry` имеют разные ответственности:
- `AVAILABLE_ACTIONS` определяет, что стратегия может выбирать.
- `ActionRulesRegistry` определяет, как выбранное действие исполняется.

## 7. BattleEngine

Управляет полным циклом одного боя.

Основные обязанности:
1. Создание снимков состояния агентов.
2. Формирование `AgentState` для каждой стратегии.
3. Получение решений от стратегий.
4. Получение соответствующих правил из `ActionRulesRegistry`.
5. Расчёт эффектов обоих действий.
6. Применение эффектов.
7. Проверка завершения боя.
8. Формирование результата.

### Порядок выполнения раунда

1. Создаются снимки обоих агентов.
2. Формируются состояния для обеих стратегий.
3. Обе стратегии выбирают действия.
4. Движок рассчитывает эффекты обоих действий на основе состояния в начале раунда.
5. После расчёта обоих наборов эффектов изменения применяются к агентам.
6. Проверяется состояние участников и условие завершения боя.

### Правила боя

- Раунды выполняются последовательно.
- Оба агента выбирают действия до применения эффектов.
- Оба действия рассчитываются относительно состояния на начало раунда.
- Последствия применяются одновременно.
- Агент, погибший в текущем раунде, всё равно выполняет выбранное действие.
- Если оба агента погибли в одном раунде — ничья.
- Если погиб один агент — второй побеждает.
- Если оба живы после достижения лимита раундов — оба побеждают.
- Проценты оставшегося здоровья не сравниваются.

Один экземпляр `BattleEngine` предназначен для одного боя. Повторный запуск должен вызывать ошибку.

## 8. BattleRules

Содержит настройки боя.

Предстоит определить:
- Максимальное количество раундов.
- Дополнительные ограничения и правила завершения боя, если они понадобятся.

## 9. BattleResult

Неизменяемая модель результата боя.

Предстоит определить:
- Представление победителя и проигравшего.
- Представление ничьей.
- Представление результата, при котором оба агента победили после достижения лимита раундов.
