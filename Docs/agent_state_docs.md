# AgentState

## 1. Описание

`AgentState` — неизменяемая модель данных, представляющая снимок текущего состояния двух участников боя.

Объект предназначен для передачи информации стратегии (`AgentStrategy`) при принятии решения о следующем действии.

`AgentState` не управляет агентами, не изменяет их характеристики и не принимает решений.

## 2. Ответственность

`AgentState` отвечает исключительно за:
- хранение характеристик своего агента;
- хранение доступных характеристик противника;
- хранение номера текущего раунда;
- предоставление неизменяемого снимка состояния для стратегии.

## 3. Структура данных

Предполагаемые поля:

| Поле | Тип | Описание |
|---|---|---|
| `own_health` | `int` | Текущее здоровье своего агента |
| `own_damage` | `int` | Текущий урон своего агента |
| `opponent_health` | `int` | Текущее здоровье противника |
| `opponent_damage` | `int` | Текущий урон противника |
| `round_number` | `int` | Номер текущего раунда |

Все поля являются обязательными на текущем этапе проектирования.

## 4. Неизменяемость

`AgentState` должен быть реализован как неизменяемый `dataclass` с использованием `frozen=True`.

После создания объекта значения его полей нельзя изменить.

Это необходимо, чтобы стратегия не могла повлиять на состояние боя через переданные ей данные.

## 5. Формирование объекта

`AgentState` формируется исключительно компонентом `BattleEngine`.

Перед началом раунда движок:
1. Получает текущее состояние обоих агентов.
2. Создаёт снимок состояния для первого агента.
3. Создаёт снимок состояния для второго агента.
4. Передаёт соответствующие снимки стратегиям.

Оба снимка должны быть созданы до вызова любой стратегии.

Это гарантирует, что обе стратегии принимают решения на основании одного и того же состояния боя.

## 6. Вычисляемые свойства

Допускается добавление вычисляемых свойств, если они непосредственно следуют из хранящихся данных.

Например:
- `own_is_alive` — жив ли собственный агент;
- `opponent_is_alive` — жив ли противник.

Такие свойства должны вычисляться на основании значений здоровья, а не храниться в отдельных полях.

## 7. Ограничения

`AgentState` не должен:
- содержать ссылку на `Agent`;
- изменять состояние участников боя;
- выбирать действия;
- рассчитывать последствия действий;
- управлять последовательностью раундов;
- содержать игровую логику, относящуюся к `BattleEngine` или `AgentStrategy`.

## 8. Требования к тестированию

Необходимо проверить:

1. Корректное создание объекта.
2. Доступность всех полей.
3. Неизменяемость объекта.
4. Отклонение некорректных типов данных.
5. Корректную работу вычисляемых свойств, если они будут реализованы.
6. Корректную обработку граничных значений здоровья.

## 9. Критерии завершения

`AgentState` считается реализованным, если:
- объект создаётся с корректными данными;
- все обязательные поля доступны;
- объект невозможно изменить после создания;
- некорректные типы данных отклоняются;
- вычисляемые свойства работают корректно, если они предусмотрены;
- все тесты проходят.
