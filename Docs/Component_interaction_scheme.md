# Схема взаимодействия компонентов MetaLab

## 1. Подготовка боя

1. Создаются два объекта `Agent` на основании соответствующих `Build`.
2. Каждому агенту назначается `AgentStrategy`.
3. `BattleEngine` получает агентов, стратегии и `ExperimentRules`.
4. `BattleEngine` начинает бой.

## 2. Последовательность боевого раунда

### Этап 1. Формирование состояния

`BattleEngine` создаёт два объекта `AgentState`.

Каждый снимок содержит:
- собственное здоровье;
- собственный урон;
- здоровье противника;
- урон противника.

Оба снимка формируются до вызова любой стратегии. Это гарантирует, что оба агента принимают решения на основании одного состояния боя.

### Этап 2. Выбор действий

1. `BattleEngine` передаёт соответствующий `AgentState` стратегии каждого агента.
2. `AgentStrategy` анализирует состояние.
3. `AgentStrategy` получает доступные действия через `ActionRegistry`.
4. Стратегия выбирает действие и возвращает его движку.

Оба действия должны быть выбраны до начала обработки последствий.

### Этап 3. Формирование эффектов

1. `BattleEngine` передаёт выбранному действию соответствующий `AgentState`.
2. Действие вызывает `supply_effect()`.
3. Метод формирует и возвращает объект `Effect`.

`Action` отвечает за формирование воздействия, но не изменяет состояние агентов.

### Этап 4. Обработка входящих эффектов

1. Каждый агент получает эффект противника.
2. Входящий эффект обрабатывается с учётом характеристик получателя.
3. Определяется фактический результат воздействия.
4. Результат фиксируется в `ActionResult`.

В MVP обработка эффекта не включает защиту, сопротивления и способности.

### Этап 5. Обработка результатов способностей

После получения результатов обработки эффектов система может использовать `ActionResult` для расчёта дополнительных эффектов способностей.

В MVP способности не реализуются.

Координацию этого этапа выполняет `BattleEngine`. Отдельный компонент обработки способностей пока не создаётся.

### Этап 6. Применение изменений

После завершения всех расчётов `BattleEngine` применяет изменения к обоим агентам.

Все результаты текущего раунда определяются до изменения состояния участников.

Это обеспечивает одновременность действий: гибель агента в текущем раунде не отменяет уже выбранное им действие.

### Этап 7. Проверка завершения боя

`BattleEngine` проверяет:
- состояние здоровья обоих агентов;
- условия победы и поражения;
- достижение лимита раундов из `ExperimentRules`.

Если бой завершён, движок формирует `BattleResult`. В противном случае начинается следующий раунд.

## 3. Ответственность компонентов

| Компонент | Ответственность |
|---|---|
| `Build` | Хранение начальных характеристик |
| `Agent` | Хранение и изменение текущего состояния агента |
| `AgentState` | Неизменяемый снимок состояния для принятия решений |
| `AgentStrategy` | Выбор действия на основании состояния |
| `ActionRegistry` | Предоставление доступных действий |
| `Action` | Базовый интерфейс игровых действий |
| `Effect` | Описание игрового воздействия |
| `ActionResult` | Фиксация фактического результата обработки действия |
| `BattleEngine` | Координация боевого процесса |
| `ExperimentRules` | Хранение правил и ограничений эксперимента |
| `BattleResult` | Хранение результата завершённого боя |

## 4. Основные архитектурные принципы

1. **Разделение ответственности.** Каждый компонент отвечает за свою область логики.
2. **Неизменяемость снимков.** Стратегии не изменяют переданный `AgentState`.
3. **Независимость выбора действий.** Оба агента выбирают действия до применения последствий.
4. **Разделение действия и эффекта.** Действие формирует воздействие, но не применяет его самостоятельно.
5. **Одновременность результатов.** Все изменения раунда рассчитываются до изменения состояния агентов.
6. **Координация вместо концентрации логики.** `BattleEngine` управляет последовательностью процесса, но не должен содержать реализацию всех игровых правил.

## 5. Отложенные возможности

- Несколько типов эффектов.
- Несколько эффектов от одного действия.
- Разделение получателей эффектов на собственного агента и противника.
- Защита, сопротивления и модификаторы.
- Способности агентов.
- Отдельный `EffectProcessor`.
- Отдельный компонент обработки способностей.

Эти возможности не входят в MVP и не должны усложнять его реализацию заранее.
